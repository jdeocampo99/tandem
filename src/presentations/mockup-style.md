# Mockup style

The page is the mockup. Show the screens, a plain name under each, and nothing else unless the brief asks for it.

## Page

- Only screens. No hero, intro paragraph, tagline, summary, "principle" callout, legend, or footer.
- Caption each screen with its plain name ("Billing", "Cancel reason"). No step numbers like "01 / 04" unless order matters and isn't obvious.
- Open questions that change the design go below the screens as a plain list, one line each. No cards, no answer chips.
- No repo maps, file citations, test plans, or implementation notes. Those belong in the research report.
- Sample data that could be mistaken for real (prices, dates) gets one plain note below the screens.

## Visual

- Use the subject project's own tokens, fonts, and components. Where it has none, pick a plain neutral look; no purple-blue gradients.
- Never use:
  - small uppercase labels above headings (eyebrows, kickers)
  - colored left or top borders on cards or callouts
  - status dots or pulsing dots next to state words ("Confirmed", "Active")
  - pill badges and tags that aren't part of the real product
  - emoji as icons
  - glassmorphism, glows, blurred halos, decorative gradients
  - three identical icon-above-heading cards
  - italic or serif words dropped in for emphasis
- One card style per screen at most. Prefer plain lists and dividers to boxes inside boxes.

## Copy

- Write what the shipped app would say. Short, specific, and useful to the person on that screen.
- End users never see implementation details: no provider, SDK, API, sync, "request complete", or "response received". Say what happened to them ("Your membership ends May 3").
- No reassurance filler ("No pressure", "Your choice", "We've got you"). No marketing taglines inside product screens.
- No "not X, it's Y", no rule-of-three padding, no em dashes.
- Banned words: seamless, effortless, elevate, unlock, empower, streamline, robust, journey, thoughtful, delightful.
- Button labels are verbs for the action ("Cancel membership", "Keep membership"). One primary action per screen.
- Headings state the screen's job ("Why are you cancelling?"), not a mood ("Before you go").

## Precedence

If the subject project has its own writing or design rules, read them; they win where they conflict with this file. This file wins over generic Lavish page-layout guidance.
